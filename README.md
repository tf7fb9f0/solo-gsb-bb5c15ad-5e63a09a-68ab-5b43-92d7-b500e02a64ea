# SRT 字幕时间校准 / 片段剪辑 / 双语合成 / 阅读速度修复 / 修订差异对照工具

一个网页小工具，包含五个相互独立的功能：

1. **字幕时间校准**：根据若干「原字幕时刻 → 视频实际时刻」锚点，对整份 SRT 字幕做时间校准。
2. **剪辑片段字幕**：输入按原视频时间填写的多个保留区间，预览并下载剪辑后重新拼接时间轴的 SRT。
3. **双语 SRT 合成**：分别提供主轨与译文轨两份 SRT，按时间全局配对后合成为主+译分行的双语 SRT。
4. **阅读速度修复**：设置最大每秒字数与单块最长秒数，按「合并次数最少」的全局规划合并相邻字幕，使每块同时满足速度与时长限制。
5. **SRT 修订差异对照**：分别提供旧版、新版两份 SRT，按保持顺序的全局动态规划对齐字幕，逐组标注未变 / 改词 / 拆分 / 合并 / 删除 / 新增，并提供 UTF-8 CSV 下载。

- 后端：Python + FastAPI
- 前端：原生 HTML/JS 单页（无构建步骤）
- 校准算法：锚点按原时刻排序，相邻锚点间**线性插值**，首尾两端按**最近一段斜率外推**，统一换算每条字幕的起止时间

## 启动

只需一条命令（依赖随容器自动安装）：

```bash
docker compose up --build
```

然后在浏览器打开：

**http://localhost:8000** （端口 `8000`）

停止：`Ctrl+C` 或 `docker compose down`。

> 不使用 Docker 时（需 Python 3.10+，`pip install -r requirements.txt`），
> 也可一条命令在本地启动，同样监听 **8000** 端口：
>
> ```bash
> uvicorn app.main:app --host 0.0.0.0 --port 8000
> ```

## 使用方法

### 功能一：字幕时间校准

1. **字幕内容**：粘贴 SRT 文本，或点击「选择文件」上传 `.srt` 文件（该内容同时供下方剪辑功能使用）。
2. **校准锚点**：至少填写 2 个锚点，格式为 `HH:MM:SS,mmm`：
   - 原时刻：字幕文件中显示的时间
   - 实际时刻：该句在视频中真实出现的时间
3. 点击 **预览校准结果**：表格逐条显示原时间、校准后时间及问题标记。
4. 若锚点校验失败（原时刻重复 / 实际时刻未严格递增 / 时间格式错误），页面会自动进行**异常定位**：
   - 标出建议剔除的最少锚点行，并用保留下来的锚点预览受影响字幕（仅建议，**确认前不改动输入**）；
   - 点击 **确认剔除并继续** 才会删除这些行并按原流程重新预览；点击 **放弃建议** 则原样保留输入；
   - 无法凑出 2 个有效锚点时提示「无法预演」，需手动修正。
5. 全部正常时点击 **导出校准后 SRT** 下载 `calibrated.srt`（保留原序号与正文）。

### 功能二：剪辑片段字幕

1. 在第 1 步粘贴 / 上传**原 SRT**。
2. 在「保留区间」中按**原视频时间**填写 1 个或多个区间（`HH:MM:SS,mmm`），表示要保留的视频片段：
   - 每个区间**起点须早于终点**；区间按起点自动排序，**重叠会报错**；
   - 区间为**左闭右开** `[起点, 终点)`，因此相邻区间端点相触（前段终点 = 后段起点）是允许的。
3. 点击 **预览剪辑结果**，表格显示每条字幕裁剪后的交集时间、拼接后的新时间与正文。
4. 点击 **下载剪辑后 SRT** 得到 `clipped.srt`。

裁剪与时间轴拼接规则：

- 对每条字幕与每个保留区间按**左闭右开**求交集：空交集的字幕直接丢弃；
- 一条字幕跨越多个保留区间时，按区间**拆成多条**输出，每条保留同一正文；
- 每段交集时间**减去该区间起点**，再**加上此前所有保留区间的时长之和**，得到剪辑后连续时间轴上的时间；
- 输出按**新起点排序**并从 1 开始**连续重编号**；
- 所有字幕都与区间无交集时禁止下载（预览会提示保留 0 条）。

### 功能三：双语 SRT 合成

页面入口：打开 **http://localhost:8000** 后滚动到页面底部的「**双语 SRT 合成**」区块（锚点 `#merge`，与上方校准、剪辑功能相互独立，使用各自的两轨输入框）。

1. 在「主轨」「译文轨」两个输入框中分别**粘贴** SRT 文本，或点击各自的「选择文件」上传 `.srt`。导出时以**主轨时间轴与条数**为准。
2. 点击 **预览配对结果**：逐条显示每条主轨、其配对译文（含各自原序号、时间与交叠毫秒数）以及**未配对译文**清单。
3. 点击 **下载双语 SRT** 得到 `bilingual.srt`。

配对与导出规则：

- 按时间**全局**配对：每条主轨可配 **0～2** 条译文，每条译文**至多使用一次**；仅有**正时长交叠**（端点相触，即前段终点 = 后段起点，不算交叠）才会配对；
- 全局优先**最大化总交叠毫秒数**；总交叠相同时优先**少漏配译文**（已配译文条数最多）；仍相同时，按已配译文**原序号（升序）序列字典序最小**决胜；
- 导出按**主轨时间与顺序从 1 连续编号**；每条主轨块内**先写主轨正文、再分行写各条译文正文**；主轨即使没有任何配对译文也**原样保留**；
- 未配对译文只在预览中列出，不写入导出文件；
- 两轨中任一条字幕出现**空时长**（终点 = 起点）或**起止时间倒置**（终点 < 起点）都会返回错误并指明是哪一轨第几条。

实现上复用同一套 SRT 解析（`parse_srt`）与时间工具（`parse_time` / `fmt_time`）。当两轨条目都按 `(起点, 终点)` 非降排列（正常 SRT 时间轴）时用带状保序动态规划求解，典型同片源两轨近线性完成；轨内条目时间回缩（相互包含 / 错位）时自动回退到最小费用最大流，对含交叉的配对仍保证上述全局最优。

### 功能四：阅读速度修复

页面入口：打开 **http://localhost:8000** 后滚动到页面底部的「**阅读速度修复**」区块（锚点 `#speed`，与上方三个功能相互独立，使用自己的输入框）。

1. **粘贴** SRT 文本或点击「选择文件」上传 `.srt`。
2. 设置两个限速参数（均为**正数**）：
   - **最大每秒字数**：每块允许的最高阅读速度（非空白字符数 / 块起止跨度秒数）；
   - **单块最长秒数**：每块起止跨度（首条起点 → 末条终点）的上限。
3. 点击 **预览修复方案**：表格逐块显示新序号、来源序号（原 SRT 序号）、时间、时长、字数、速度与合并正文。
4. 存在可行方案时点击 **下载修复后 SRT** 得到 `speed_fixed.srt`（从 1 连续重编号）；无可行方案时预览会指出**无法修复**及具体原因，下载按钮保持禁用。

修复与规划规则：

- **字数统计**：正文中每个**非空白字符**计一字（空格、制表符等不计）；
- **速度**：块速度 = 块内非空白字数 ÷ 块起止跨度（末条终点 − 首条起点），须 ≤ 最大每秒字数；块跨度同时须 ≤ 单块最长秒数，**两个限制须同时满足**（单条字幕自成一块时同样受限）；
- **输入校验**：任一条字幕出现**空时长**（终点 = 起点）、**起止倒置**（终点 < 起点）或**轨内重叠**（前条终点 > 后条起点）都会报错并指明位置；
- **合并限制**：仅允许合并**时间相邻且间隔 ≤ 500ms** 的连续字幕（间隔更大处必须切开）；合并块沿用**首条起点、末条终点**，正文按原顺序**换行拼接**；
- **全局规划**：以**合并次数最少**（= 条数 − 块数）为先；仍并列时选择**切分位置序列字典序最小**的方案（切分位置 = 相邻两条之间的切开处，按条目序号升序）；
- **无法修复**：若不存在满足全部限制的分块方案（例如某条自身时长已超单块上限，或尽量合并后速度仍超限），预览返回 `feasible: false` 与原因，导出接口返回 `400`。

实现上复用同一套 SRT 解析与导出格式；规划采用后缀动态规划（`plan_speed_fix`），利用「终点严格递增 ⇒ 块跨度随块尾单调」提前剪枝。

### 功能五：SRT 修订差异对照

页面入口：打开 **http://localhost:8000** 后滚动到页面底部的「**SRT 修订差异对照**」区块（锚点 `#diff`，与上方四个功能相互独立，使用自己的旧版 / 新版输入框）。

1. 在「旧版 SRT」「新版 SRT」两个输入框中分别**粘贴** SRT 文本，或点击各自的「选择文件」上传 `.srt`。
2. 点击 **预览差异对照**：结果按**对齐组**展示，每组同时列出旧版与新版各条字幕的**原序号、时间、正文**，并用彩色标签区分六种类型：
   - **未变**：1:1 匹配，去空白与标点后正文完全相同（仅时间或标点差异也算未变）；
   - **改词**：1:1 匹配但正文有改动；
   - **拆分**：旧版 1 条对应新版 2 条；
   - **合并**：旧版 2 条对应新版 1 条；
   - **删除**：仅旧版存在（新版缺失）；
   - **新增**：仅新版存在（旧版缺失）。
3. 点击 **下载 UTF-8 CSV** 得到 `srt_diff.csv`（带 UTF-8 BOM，Excel 直接打开中文不乱码），每个对齐组一行，含组号、差异类型、相似度、时间差与双方原序号 / 时间 / 正文。

对齐与判定规则：

- **复用同一套解析器**（`parse_srt`）解析两版 SRT，保留各自文件中的原序号；
- 在**保持两版原有顺序**的前提下做**全局动态规划**对齐，每个对齐组只允许 **1:1、1:2（拆分）、2:1（合并）** 三种匹配以及**单侧跳过**（删除 / 新增）；
- 相似度基于**去除全部空白与标点、并做小写化（全角转半角）**后的正文，用序列匹配比率（0～1）计算；多对一组按组内各条正文**拼接后整体**计算，只有相似度 **≥ 0.5** 的组合才允许匹配；
- 全局目标：先**最大化所有匹配组的相似度总和**；总分相同时，再**最小化所有匹配组的时间差总和**（每组时间差取两侧字幕时间区间中点之差的毫秒数）；单侧跳过不计分，因此只有在确实不存在更优匹配时才会判为删除 / 新增；
- 拆分、合并组**按整段对照**（旧 1 段对新 2 段 / 旧 2 段对新 1 段的整体相似度达标即可），不会把拆分或合并后的段落逐条对撞而误报成改词、删除或新增；若拆并同时伴随正文改动，预览会额外标注「正文同时有改动」；
- **输入校验**：任一版 SRT 无法解析，或任一条字幕出现**空时长**（终点 = 起点）、**起止时间倒置**（终点 < 起点），都会返回明确错误并指明是哪一版第几条；两版条目数乘积超过对齐计算上限时也会报错提示。

实现上，`align_diff` 以三行滚动的保序网格 DP 求解五种转移，相似度定点化为整数后与时间差编码进同一整数目标（相似度位严格优先），回溯即可得到全部对齐组。

## 规则说明

### 锚点校验（不满足会被拒绝并提示）

- 至少 2 个锚点；
- 原时刻不得重复；
- 映射后的实际时刻必须严格递增。

### 锚点异常定位（剔除建议）

锚点校验失败时，后端按以下规则求一个修复方案：

1. 将锚点按**原时刻**排序，选出原时刻与实际时刻**都严格递增**的最长子序列（至少含 2 点），即需要剔除的锚点最少；
2. 多解时先最大化**首/尾原时刻**（全局最小、最大原时刻）锚点的保留数量；
3. 仍多解时，按待剔除项的**原输入行号序列**字典序最小决胜；
4. 无法解析的时间格式行必然在剔除之列；有效锚点不足 2 点则返回「无法预演」。

该逻辑由 `POST /api/suggest` 提供，返回剔除行号、逐行原因，并用保留锚点复用校准预览展示受影响字幕。

### 问题检测（存在任一问题时禁止导出）

| 问题 | 判定 |
| --- | --- |
| 负时间 | 校准后起点或终点 < 0 |
| 起止倒置 | 校准后终点 ≤ 起点 |
| 与下一条重叠 | 本条终点 > 下一条起点 |

前端预览会标红问题行，后端导出接口同样强制校验，有问题返回 400。

## API

校准功能：

- `POST /api/preview` — 请求体 `{"srt": "...", "anchors": [{"orig": "00:01:00,000", "actual": "00:01:02,500"}, ...]}`，返回逐条校准结果与问题标记。锚点校验失败返回 `400`，`detail` 为 `{"type": "anchor_invalid", "message": "..."}`。
- `POST /api/suggest` — 同请求体；锚点校验失败时的异常定位建议。
  - 可行时返回：`feasible: true`、`remove_rows`（建议剔除的输入行号，1 起）、`kept`（保留锚点）、`removed`（逐行剔除原因）、`preview`（用保留锚点得到的校准预览，结构同 `/api/preview`）或 `preview_error`（SRT 无法解析时）。
  - 不可行时返回：`feasible: false` 与 `reason`（无法预演原因）。
- `POST /api/export` — 同 `/api/preview` 请求体；无问题时返回 `calibrated.srt` 文件下载，有问题返回 `400`。

剪辑功能（独立 API，复用同一套 SRT 解析与时间格式化）：

- `POST /api/clip/preview` — 请求体 `{"srt": "...", "intervals": [{"start": "00:01:00,000", "end": "00:02:00,000"}, ...]}`；返回 `interval_count`、`total_duration`（拼接后总时长）、`entry_count` 与逐条结果（新序号、原序号、交集原时间、剪辑后时间、正文）。区间为空 / 起点不早于终点 / 解析失败 / 区间重叠时返回 `400`。
- `POST /api/clip/export` — 同请求体；返回按新起点排序并连续重编号的 `clipped.srt` 文件下载；无任何字幕落入保留区间时返回 `400`。

双语合成功能（独立 API，复用同一套 SRT 解析与时间格式化）：

- `POST /api/merge/preview` — 请求体 `{"main": "...", "translation": "..."}`（均为完整 SRT）。返回 `main_count`、`trans_count`、`matched_count`、`unmatched_count`、`total_overlap_ms` / `total_overlap`（最优总交叠）、逐条 `entries`（主轨序号/原序号/时间/正文及其 `translations`，每条译文带原序号、时间、交叠毫秒数与正文）以及 `unmatched`（未配对译文）。任一轨 SRT 无法解析、出现空时长或起止倒置时返回 `400`。
- `POST /api/merge/export` — 同请求体；按主轨时间与顺序从 1 连续编号，主轨正文与各配对译文正文分行写入，返回 `bilingual.srt` 文件下载（主轨无译文仍保留）。校验规则同上，失败返回 `400`。

阅读速度修复功能（独立 API，复用同一套 SRT 解析与导出格式）：

- `POST /api/speed/preview` — 请求体 `{"srt": "...", "max_cps": 20.0, "max_block_seconds": 7.0}`（两个参数均须为正数）。返回 `feasible`、`entry_count`、`block_count`、`merge_count`（合并次数）与逐块 `blocks`（新序号 `seq`、来源原序号 `sources`、起止时间、`duration_ms`、非空白字数 `chars`、速度 `cps`、合并正文 `text`）；无可行方案时返回 `feasible: false` 与 `reason`（无法修复原因）。参数非正数、SRT 无法解析、空时长 / 起止倒置 / 轨内重叠时返回 `400`。
- `POST /api/speed/export` — 同请求体；返回从 1 连续重编号的 `speed_fixed.srt` 文件下载（合并块沿用首条起点、末条终点，正文按原顺序换行拼接）；无可行方案时返回 `400` 并附无法修复原因。

修订差异对照功能（独立 API，复用同一套 SRT 解析与时间格式化）：

- `POST /api/diff/preview` — 请求体 `{"old_srt": "...", "new_srt": "..."}`（均为完整 SRT）。返回 `old_count`、`new_count`、`group_count`、`counts`（六种类型的组数统计）、`matched_group_count`、`total_similarity` / `avg_similarity`，以及逐组 `groups`：`seq`（组号）、`type`（`unchanged` / `changed` / `split` / `merge` / `delete` / `add`）、`old` 与 `new`（双方各条的顺序号、SRT 原序号 `index`、时间、正文），匹配组另附 `similarity`、`gap_ms`（中点时间差毫秒）与 `text_changed`（拆分 / 合并组正文是否同时有改动）。任一版 SRT 无法解析、出现空时长或起止倒置、对齐规模超限时返回 `400`。
- `POST /api/diff/export` — 同请求体；返回带 UTF-8 BOM 的 `srt_diff.csv` 文件下载（RFC 4180 转义，字段为：组号、差异类型、相似度、时间差(ms)、旧版序号、旧版时间、旧版正文、新版序号、新版时间、新版正文）。校验规则同上，失败返回 `400`。
